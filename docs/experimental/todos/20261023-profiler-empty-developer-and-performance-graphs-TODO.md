## 三张图的定义

| 图表 | 首版统计口径 | 呈现与边界 |
|---|---|---|
| **帧率**，FPS | 主曲线为喜鹊后端处理帧率：与现有 `StepTimer::PrepareForRender` 的计数事件一致，按实际经过时间统计。 | 标注“处理帧率”，不含补帧输出。FG 开启时可以叠加内容输出／提交帧率，沿用来源标签与未知状态；不改变原工具栏计数语义，不把重复 UI 呈现计入内容 FPS。 |
| **帧间隔**，ms | 相邻两次同一后端处理事件的实际 `steady_clock` 时间差。 | 标注“处理帧间隔”，与主 FPS 曲线口径一致。保留均值和最大值以看见卡顿；不用 `1000 / FPS` 生成伪逐帧曲线，也不把绘图刷新间隔当帧间隔。 |
| **效果器耗时**，ms | 同一个有效查询样本内的效果 pass 耗时先求和，再进行时间桶统计。 | 主标题统一为“效果器耗时”。提示说明当前已测范围；只测到部分原生后端工作时显示简短“部分统计”标记，不把 CPU 等待、Present、采集耗时或 SDK 未测量部分拼成总 GPU 时间。 |

主 FPS 的处理事件可能包括同一个捕获帧的再次处理，与 FG 输出统计里的真实内容帧计数应明确区分。SDK 只提供一批输出的数量时，可以展示它的帧率；没有逐帧时间戳就不承诺补帧输出的逐帧间隔。真实屏幕扫描节奏不属于首版统计范围。

效果器耗时列表现有“跳过不执行 pass 后求均值”与新曲线“单个已测处理样本总计”的分母可能不同。实施时明确两者说明，或在确认不损害逐效果查看用途后统一口径；不能直接把 `_lastestAvgEffectTimings` 相加并称为逐帧曲线。

## 数据与绘图设计

- **观察窗口**：首版最近 10 秒，共用时间轴。建议按 100 ms 固定时间桶聚合，每条历史显示 100 桶，内部另保留 12 桶用于最老点的 FPS 回看；FPS 使用约 1 秒滚动窗口，效果器耗时与帧间隔保留桶内均值、最大值和有效样本数。100 ms 桶用于保留数据，绘图仍沿用最多每 500 ms 一次的独立刷新；正常内容帧带来的绘制可直接读取最新快照。
- **事件处采集**：处理计数／间隔在后端真实事件处记录；GPU 查询在完成时聚合每个有效结果，不能只保留最后一个。查询槽保留处理帧的 CPU 时间锚点、会话／效果链版本，延迟返回的结果归回原时间桶；时间锚点不是 GPU 绝对执行时刻。
- **明确缺测**：每桶包含计数、有效性及覆盖范围。查询尚未返回、被跳过、超时禁用、来源未知都不填成 0 ms；同一旧样本多次重绘不生成新样本。实际确认没有处理事件的 FPS 窗口可以为 0，帧间隔和效果器耗时则留空。
- **尖峰保留**：均值线配细最大值线或范围标记。即使前端一次消耗了多个完成结果，也先保留各桶最大值；不需要保存无界逐帧数组，也不在首版增加百分位数、导出或通用监控系统。
- **线程归属**：后端拥有处理及 GPU 采样聚合，前端拥有既有 FG 计数与最终图形历史。Renderer 统一交付带版本／时间的快照，OverlayDrawer 负责展示。可用专用固定容量历史类型隐藏桶维护；不让 UI 访问 GPU 对象或反复解析日志。
- **同步开销**：复用现有前后端交接方式，短锁只交换／复制有界数据；GPU 查询、绘制和字符串格式化均在锁外。查询继续采用不 flush、不等待的回收方式，不新增每帧堆分配、强制 GPU 同步或新的呈现节拍器。
- **生命周期**：开关性能分析窗口沿用 `StartProfile/StopProfile`；新增采集随其启停，基础 FPS/FG 统计仍按原逻辑运行。GPU 查询禁用或没有效果 pass 时，帧率和帧间隔仍可独立工作。重新打开从新会话开始；关闭后清理图表历史。效果链切换，即使 pass 数相同，也需递增版本并丢弃旧查询；捕获会话、设备或资源重建同样断开历史。
- **暂停与断流**：明确区分暂停、等待新内容、计时不可用。无新采样时不重复旧数值填满曲线；恢复时断开暂停段，不能把用户暂停时间画成普通卡顿。正常运行中的真实长间隔应保留为尖峰，不能仅按“大于阈值”全部丢掉。
- **现有 ImGui 能力**：每张图采用紧凑的当前值、均值／最大值、曲线和单位。优先用现有 DrawList 绘制时间坐标和缺测断点，复用一个局部绘图函数；不新增绘图库依赖。Y 轴从零开始，扩张及时、收缩缓慢，避免每次更新跳动；暂停期间保留可读刻度。
- **布局**：每图建议约 50–60 个逻辑像素高，适配现有 310 逻辑像素宽度；沿用最大高度和滚动条，图表下保留效果器耗时明细。三图单位独立但横轴一致，颜色沿用主题，明暗主题及 HDR 覆盖层复用既有颜色路径。

## 首版边界

本方案不承诺游戏内部 CPU/GPU 帧时间、端到端延迟、实际显示扫描间隔或所有原生 SDK 的完整 GPU 耗时。若以后需要这些指标，必须先补齐对应数据源与验证，再作为扩展任务。首版优先交付可靠的处理节奏、已有范围内的效果器耗时走势，以及不留空标题的性能分析窗口。
