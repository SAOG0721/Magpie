## 1. 已确认需求与参数约定

| 项目 | 本次规划 |
|---|---|
| SM86 依赖 | `dlssg_for_sm86` 0.3.5 → 0.4.0，配套 `nvngx_dlssg.dll` 310.9.1.0 → 310.9.16.0 |
| DLSS SR 预设 | 自动、A、B、C、D、E、F、J、K、L、M；用户确认保留旧预设请求选项，**默认 K** |
| DLSS FG 预设 | 自动、A、B、C；建议默认自动，沿用当前不强制预设的行为 |
| DLSSNR 抗闪烁时间 | 用户确认 **5–200 ms，步进 5 ms，默认 80 ms** |
| 参数作用范围 | 随对应效果实例保存；NR 时间是整个 NR 链末端的一项参数，不给 Pass 2 / 3 各增加一份 |
| 生效方式 | SR / FG 预设首版按现有“重新启动缩放”流程重建 Feature；NR 时间争取实时应用，下一有效捕获帧采用新时间常数 |

术语：界面使用“模型预设”或“渲染预设”，说明为向运行库提交的请求。预设字母不等于一份独立 DLL，也不保证运行库存在或实际采用对应模型。保留“自动”用于不强制指定预设；SR 的“自动”与默认选中的 K 是两个不同选项。

默认值迁移：按用户“默认 K”的要求，新建 SR 效果和旧配置缺少新字段时均采用 K；已明确保存的有效选择继续保留。此项相对当前固定 J 是有意的默认行为变化，需要在更新说明和回归中体现。NR 缺少时间字段仍为 80 ms；FG 缺少预设字段仍为自动。

### 已确认的调用链与缺口

1. `OverlayDrawer.cpp:1030–1032` 的按钮和 `Renderer.cpp:1865–1866` 的动作分发都调用 `TakeDisplayedScreenshot()`。恢复播放后两入口都能用，与它们共同的截图处理路径有关，不能只修快捷键。
2. `RendererScreenshot.cpp:56–101`：仅输出模式直接保存 `_frontendPresentedBaseTexture`；包含输入的模式则排队 `_backendScreenshotRequest`，设置 `_forceNextRender=true`，并等待匹配的真实画面呈现。**已有强制重绘，不应重复添加同一个 flag 或只延长 10 秒超时。**
3. `_SnapshotScreenshotInput()` 在 `Renderer.cpp:3992` 的后端效果执行前取得原始尺寸输入；输入快照随后必须借助共享呈现槽移交前端。`Renderer.cpp:1297–1310` 仅在成功提交、`contentFrame=true` 且三元帧身份匹配时开始保存。
4. **可从代码确定的停帧缺口**：`Renderer.cpp:4198–4201` 对无新捕获帧的软件 FG／未改历史的代理 FG 提前返回，发生在输入快照之后、共享槽发布之前。此时“强制重绘”并不能让截图快照到达前端。即使代理路径发布重绘，`:1108` 会把它归入 idle，`:1180` 的 `contentFrame` 为 false，仍不满足截图完成条件。恢复新画面后重新经过正常发布／呈现，才可能完成未超时请求。
5. **不能过度归因**：无 FG、捕获健康且已有有效帧时，当前 `_forceNextRender` 路径理论上应继续完成截图。若无 FG 也失败，还需确认请求是否到达、`IsCaptureInterrupted`／帧身份变化／同步槽状态及实际运行版本；不能把第 4 项当作所有无 FG 故障的已证实根因。
6. 捕获层明确允许健康静态源长期没有新帧；但发生显式中断时，`Renderer.cpp:3551–3562` 会先阻止重绘。WGC 显示光标会重启捕获，故复现需区分“纯暂停无新帧”与“打开工具栏伴随捕获重启”。正常无新帧不应被当成捕获错误。
7. 现有截图测试主要覆盖内容选项、帧身份比较、命名、落盘与静态接线；没有覆盖暂停后请求 → 跨线程快照 → 保存的完整路径。源代码缺口与用户现场的触发分支需分开记录。
