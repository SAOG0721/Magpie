## Exact dependency

The official [0.4.0 release](https://github.com/sdli1995/dlssg_for_sm86/releases/tag/0.4.0) points to tag commit `6f047bdc885e861575e8b049413ca31dc171a924`. The sole release asset is `dlssg-release-0.4.0-x64.zip`, 80,551,324 bytes, SHA-256 `5865360c3295038f0ff979d303bb7eb9437eec09fbc08686967d3b5d41d9c019`; the downloaded bytes match the GitHub asset digest. Per-file paths, lengths, hashes, full file version and Authenticode observations are in [the identity record](20261022-sm86-040-identities.json), also enforced by `src/Shared/DlssgSm86Package.h`.

`nvngx_dlssg.dll` is NVIDIA-signed, Authenticode **Valid**, file version **310.9.16.0**. Upstream proxy/backend/kernel pack bear the upstream self-signed certificate; local Windows verification reports **UnknownError**, not a trusted NVIDIA signature. No trust-store changes were made.

The package carries proxy, two managed configuration variants, upstream license/notices, backend, FG kernel resource DLL, and NVIDIA FG runtime. Paths match the official release manifest. The upstream INSTALL documents proxy-relative resolution, SR files unused under `SuperResolution.Mode=Off`, and XeSS-FG resources only used by that engine. This package selects `Engine=DLSS`; unrelated SR/XeSS-FG/alternative proxies are omitted. The existing Magpie SR/XeSS libraries remain independent.

## Loader and upgrade contract

The entire tree is copied into Magpie's private cache keyed by release-archive identity plus managed INI identity. Every required file is hash-verified and held open before loading. Backend and runtime module paths must match their exact separate subdirectories in that tree; duplicate or foreign module mappings remain errors. The FG kernel pack is a resource-only DLL; its file is locked and verified without treating its presence as GPU execution.

A private missing-path runtime request still activates the lazy proxy. NGX PathListInfo continues to use the actual returned runtime directory and application directory in the existing shared D3D11/D3D12 initialization. Preparation, discovery, capability, Feature creation and Evaluate remain separate stages. Preparation failure remains sticky, requiring process restart.

Managed INIs use `[DLSSG] Optimized=1, Preset=Auto`, `[FrameGeneration] Engine=DLSS, MaxGeneratedFrames=3`, `[Runtime] Mode=Bundled` and `[SuperResolution] Mode=Off`. Removed legacy keys (`CacheDirectory`, `SkipRepeatedRealCopy`, `HardwareBilinear`) are omitted. RTX 40/50 use `AccelerateNewerGpus=1`, PTX, with `ForceSM86Route=0` and `SimulateAmpere=0`, following the new route rather than the old architecture-bridge test mode. Policy remains bounded to physical SM75/86/89/120 and maximum 4x.

Fetch retains the exact archive/extraction and moves the old selected dependency to a sibling backup before installing the verified staging tree, with recovery on failed final move. Packaging only archives the exact former NVIDIA FG root DLL. Updater obsolete-file cleanup only accepts recorded former hashes; its existing transaction preserves rollback copies for replacements. No deletion of `%LOCALAPPDATA%/DlssgSm86` or old Magpie caches occurs.

## Per-effect FG requests

Stable values are Auto=0, A=1, B=2, C=3; missing/nonfinite/fractional/out-of-range values resolve to Auto. Renderer carries the request into settings and existing Initialize/Resize/rebuild paths. The normal effect-parameter restart-scaling flow recreates the Feature and retires its old queue/history. No proxy/config reload is needed.

The feature-level request is submitted before CreateFeature: A requests UI recomposition=0/Lite=0; B requests 1/0; C requests 0/1. Auto writes neither key. Keys are `DLSSG.UserInterfaceRecompositionEnabled` and `DLSSG.LiteCandidateBlendingEnabled`. No per-Evaluate mutation or extra Evaluate is introduced. C reaches this path only after the complete 310.9.16 package verification.

The official [ARCHITECTURE](https://github.com/sdli1995/dlssg_for_sm86/blob/6f047bdc885e861575e8b049413ca31dc171a924/docs/ARCHITECTURE.md) documents creation-time UI-recomposition resolution and driver profile > application parameter > built-in priority. Its INI forced preset hook would supersede these; managed `Preset=Auto` leaves that hook unpinned. [INSTALL](https://github.com/sdli1995/dlssg_for_sm86/blob/6f047bdc885e861575e8b049413ca31dc171a924/docs/INSTALL.md) identifies the C Lite parameter. These are application requests, not a promise to override driver policy. No verified public effective-model query is available here; parameter readback is not model confirmation. Logs distinguish requested/submitted, unknown effective preset, missing B inputs, Feature creation and first successful Evaluate API return (GPU completion still separate).

HUDLess/UI/UIAlpha remain honestly marked never provided. B stays selectable and its input limitation is diagnostic-only. The dropdown displays plain A/B/C with no added description below it. Submission failure returns failure, retaining the saved request rather than silently submitting a different letter.
