# XeSS_FrameGeneration（0.6.11）

性能分析的“图表 → 帧间隔”现可显示随附运行库下 2×／3×／4× 的逐次输出间隔。数据来自真实 provider 输出调用，包含补帧，不由输入帧间隔或 FPS 倒算；不代表显示器实际扫描间隔。分析器关闭及空闲重放时停止采集，切换、失败和丢样处断开统计。原生路径仅增加被动观测，不调整其补帧节奏；未知原生运行库保持正常功能并显示缺测。

效果选择器只提供一个 XeSS_FrameGeneration，倍率可选 2×～4×。新建时默认 2×、AMD 光流、质量。

重复帧检测统一使用“帧率与刷新”的通用设置。启用空闲持续重绘后，约 0.5 秒没有新内容时按有效重绘率重绘缓存；不会额外插帧，也不增加真实输入帧率。 DLSS、XeSS、FSR3 与 VFG 均移除效果级开关，旧字段迁移移除且不覆盖通用保存值。

WGC 重复时间戳仍跳过并保留历史，倒退/无效时间戳仍走恢复路径。XeSS 空闲重绘使用 SDK 非生成呈现，暂时关闭 XeLL 限速；保留 XeLL marker 与独立递增的 SDK 呈现 ID，恢复时先启用 XeLL 再启用 FG，并重置历史。

首次读取旧版配置时，会将所有效果组里的旧 x2/MFG 替换为统一效果器。迁移倍率为 2×，光流方法和质量保留原选择；缺失字段使用旧效果器默认语义。原效果组、配置文件引用、其他效果顺序及缩放属性保留。同组重复 XeSSFG 保留第一个。迁移前自动备份，保存失败不完成启动迁移。今后导入旧效果组也执行转换，新效果器已经保存的参数不会再次重置。

2×和 Intel 原生路径使用 SDK 原行为。非 Intel 显卡的 3×/4×自动启用多帧兼容及节奏修复，没有额外兼容开关。2×／3×／4×均可选择无光流、AMD 或 NVIDIA 光流。NVIDIA 光流需要当前 GPU、驱动和质量档通过原有能力检查，倍率不会绕过这些检查。未知运行库、已被修改的补丁位置或初始化失败会明确报错，不将请求倍率静默改为 2×。

兼容路径限定随附 `libxess_fg.dll 1.3.1.78`，SHA-256 为 `EC5E0C65E075570C6EDE72618BB666D0BE0C2E10B2EA9762C0FE8CB8E375AB27`。应用只修改内存，并在交换链、XeFG/XeLL 上下文退出后恢复；无法确认退出或恢复成功时，本进程停止接受新的 XeSSFG 会话，需要重启 Magpie。

## 2026-09-14 历史实现与验证

2026-09-14 修复：捕获会话序号在连续捕获时保持不变，旧计时器却把它当作逐帧编号，导致非 Intel 3×/4×每帧重置插帧历史、时间估计恒为零。现在仅在会话变化时按会话重置，以帧 ID 判断提交中是否跳过捕获帧；资源换代、时间倒退、重复帧和长暂停仍重置。显示名称与 `DLSS_FrameGeneration` 对齐，内部效果 ID 和已保存参数不变。

修复后验证（RTX 5070 Ti）：

- 计时回归：同会话连续 120 帧只在首帧重置；覆盖捕获重启、资源换代、跳帧、时间倒退及暂停。
- SDK 合成测试接入正式计时器，覆盖捕获会话及资源换代。每轮预热后 45 次提交分别返回 90／135／180 帧，均为完整倍率；同进程恢复原生 2×成功。
- 真实 Magpie WGC＋AMD 质量光流、SDR 窗口模式，关闭 RTSS 后完成 2→3→4→2→DLSSNR＋4×。累计 SDK 帧数／提交数分别为 951/480、1066/360、1425/360、957/480、1413/360；包含启动和捕获历史重建时的单帧输出。4×连续两个 120 次提交窗口均输出 480 帧。DLSSNR 组合启用 50% 输入分辨率、单次 Multi Pass 和低频时域重建。

RTSS 兼容性尚有独立问题：一次开启 RTSS 的多轮切换，在新交换链初始化时经过 `RTSSHooks64 → nvapi64_impl → D3D12Core` 触发 `FAST_FAIL_GUARD_ICALL_CHECK_FAILURE`。改用测试进程名仍会受到 RTSS 全局 60 FPS 限制；退出 RTSS 后同进程切换通过。本次未修改 RTSS 设置。慢启动修复已在 RTSS 开启时验证；独立的重建期注入崩溃仍未修复。

这些结果不证明显示器已均匀显示全部生成帧。日志中的 provider 间隔和 SDK 计数不能替代 ETW／PresentMon 的显示事件。游戏画质、HDR、VRR、30/45/60 FPS 波动输入、长时间运行及 NVIDIA 光流路径仍待实测；本次以实验版本交付。5×～8×未开放。

2026-09-14 慢启动修复：3×／4×使用 SDK 时间域内的固定输出期限，过期时隙不再额外补等一个完整间隔；fallback 路径同步修正。下一轮重新定相，启动估计降低单个慢样本的持续影响。没有新增设置，也不需要把 Reflex 切换为 Async。
